# บันทึกการข้ามด่าน push — **ช่องยกเว้นต้องมีร่องรอย**

🔑 **เหตุที่ไฟล์นี้มีอยู่** (14 ต.ค. 2569 · เกณฑ์สามข้อของคุณส้ม)
ส่องช่องยกเว้นทุกช่องในรีโปนี้แล้วพบว่า `SKIP_PREPUSH=1` กับ `ALLOW_FAST_PUSH=1`
เป็น **ช่องที่ทรงอำนาจที่สุด** (ข้ามด่านทั้งอัน / ข้ามกติกาความถี่) แต่:
```
ใครตรวจแทน?      — **ไม่มี**
บังคับอธิบายไหม?  — **ไม่**
โชว์ทุกรอบไหม?    — **ไม่** ⇒ ใช้แล้วไม่เหลือร่องรอยที่ไหนเลย
```
⇒ ⇒ ตามเกณฑ์นั้น **มันไม่ใช่ช่องยกเว้น มันคือรูที่เราเขียนเอกสารกำกับไว้**

✅ สิ่งที่เปลี่ยน: ฮุคจดบรรทัดลงไฟล์นี้ทุกครั้งที่ช่องถูกใช้ **และพิมพ์จำนวนครั้งทุกรอบ**
   (ไม่ใช่พิมพ์ตอนตก — ของที่โชว์ตอนตกคือของที่ไม่มีใครอ่านตอนมันมีประโยชน์)
🚫 **ฮุคไม่บล็อกการใช้ช่อง** — เจตนาคือให้ "ข้าม" เป็นการตัดสินใจที่มีร่องรอย ไม่ใช่สิ่งที่ทำไม่ได้
⚠️ ขอบเขต: ลบไฟล์นี้หรือแก้ฮุค ⇒ ร่องรอยหาย ⇒ **ชั้นสุดท้ายยังเป็นคน** (เขียนไว้ ไม่กลบ)
   แต่ไฟล์นี้อยู่ใน git ⇒ การลบจะเห็นใน diff ซึ่งต่างจากเดิมที่ไม่มีอะไรให้ลบเลย

## 🔴 ช่องที่ **บันทึกนี้จับไม่ได้** — เขียนไว้ ไม่กลบ (14 ต.ค. 2569)
`git push --no-verify` **ข้ามฮุคทั้งอันตั้งแต่ก่อนโค้ดบรรทัดแรกจะรัน**
⇒ ตัวจดอยู่ *ในฮุค* ⇒ มันไม่ได้รัน ⇒ **ไม่มีแถวในตารางนี้ และไม่มีอะไรฟ้องที่ไหนเลย**
🔑 ⇒ ตารางนี้จึงบอกได้แค่ **"ช่องที่ผ่านฮุคถูกใช้กี่ครั้ง"** ไม่ใช่ "ด่านถูกข้ามกี่ครั้ง"
   ⇒ ⇒ และ **ไม่มีฮุคไหนปิดช่องนี้ได้** เพราะมันคือการสั่งไม่ให้ฮุคทำงาน
   (ถ้อยคำตั้งต้นเป็นของฝั่งจอ: *"ถ้าบังคับให้มีเหตุก่อนข้าม คนจะใช้ `--no-verify` แทน
    แล้วเราเสียร่องรอยทั้งหมด"* ⇒ เขาใช้เป็นเหตุผลว่าทำไมต้องไม่บล็อก · ผมใช้ต่อว่า
    **มันเป็นขอบเขตของตัวบันทึกเองด้วย** ไม่ใช่แค่เหตุผลเชิงออกแบบ)
✅ ที่ตรวจแทนได้จริง (ไม่ใช่ฮุค): **ฝั่งปลายทาง** — คอมมิตที่ขึ้น origin โดยไม่มีผล build
   ที่ตรงกับมัน ⇒ สืบย้อนได้จาก Netlify deploy log · **ยังไม่ได้ทำ และไม่อ้างว่าทำแล้ว**
🔑 กฎที่ใช้กับตารางนี้เอง: **ตัวบันทึกที่อยู่ในของที่ถูกข้ามได้ จะบันทึกไม่ได้ตอนที่สำคัญที่สุด**
   รูปเดียวกับ `watcher-must-live-outside` และ `check-chain-floor` ที่ต้องอยู่นอกสาย
