# ใบตรวจมาตรฐาน “เหมือน ZORT 100%” ต่อหนึ่งหน้า

งาน `t_mu1dfgj7` · จัดทำ 14 ก.ย. 2569

เอกสารนี้แก้ปัญหาเกณฑ์เดิมที่นับเพียงว่า “มีหน้า” แล้วให้ทั้งหน้าเป็นหนึ่งคะแนน หน้าเดียวต้องแตกเป็นของที่ผู้ใช้เห็นและกดได้จริงทีละรายการ: ปุ่ม เมนู ช่องกรอก การ์ด คอลัมน์ กราฟ ตัวเลข สถานะว่าง/ผิดพลาด และข้อจำกัดสิทธิ์

หลักฐานที่ใช้รอบนี้:

- ฝั่งเรา: อ่าน source ของ `gucut-next` ที่ commit `f36f655` เฉพาะไฟล์ที่ไม่มีการแก้ค้าง ได้แก่ `app/core/purchases/new/page.tsx`, `app/core/stock/page.tsx` และ `lib/product-menu.ts`
- ฝั่งท่อ: `gucut-web` commit `3f0336c` และสัญญาใน `netlify/lib/core-stock.mjs`
- ฝั่ง ZORT: `~/claude-shared/zort-ฟังก์ชันจริงทุกหน้า.md` ซึ่งมีข้อมูล `/Product/list` และ `/Bundle/Details`; ยังไม่มีผัง `/Buy/Add`
- ไม่ได้ใช้คีย์ ไม่ได้ POST ZORT และไม่ได้เปิดจอ ZORT ในรอบนี้ รายการที่ต้องอาศัยสองอย่างนั้นเขียนว่า **ต้องดูจอ ZORT**

## กติกาตัดสิน

ใช้สถานะต่อหนึ่งรายการย่อยดังนี้:

| สถานะ | ความหมาย | นับว่าตรง |
|---|---|---:|
| ✅ ตรง | เห็นและทดลองสองฝั่งด้วย input เดียวกัน ผลและสถานะหลังทำตรงกัน มีหลักฐานทั้งสองฝั่ง | 1 |
| 🟡 บางส่วน | มีทั้งสองฝั่ง แต่ขาดพฤติกรรม ช่อง หรือผลบางอย่างที่ระบุชัด | 0 |
| ❌ ไม่ตรง | ฝั่งหนึ่งไม่มี กดไม่ได้ หรือให้ผลผิดจากอีกฝั่ง | 0 |
| ⏳ ต้องดูจอ ZORT | หลักฐานฝั่ง ZORT ไม่พอ ห้ามเดาและห้ามนับผ่าน | 0 |
| 🔐 ติดสิทธิ์ | มีเส้นหรือจอ แต่สิทธิ์ที่ใช้ตรวจไม่ถึง จึงยังยืนยันผลไม่ได้ | 0 |
| ➕ ของเราเพิ่มเอง | ความสามารถเสริมที่ไม่แทนของ ZORT แยกไว้นอกตัวหาร | ไม่นับ |

คะแนนหน้าคือ `จำนวน ✅ / จำนวนรายการในฝั่ง ZORT ที่บันทึกครบ` และประกาศ 100% ได้ต่อเมื่อครบพร้อมกัน:

1. เก็บ inventory ฝั่ง ZORT จากจอจริงครบทั้งหน้า รวมเมนูที่ต้องเปิดก่อนเห็นรายการย่อย
2. ไม่มี 🟡, ❌, ⏳ หรือ 🔐 เหลือในรายการฝั่ง ZORT
3. ตัวเลขทุกตัวผ่านการเทียบด้วยบัญชี ช่วงเวลา ตัวกรอง คลัง สถานะ หน่วย และเวลาถ่ายข้อมูลเดียวกัน
4. ปุ่มเขียนทุกรายการทดสอบผลหลังเขียนและทางย้อนกลับ ห้ามนับจาก HTTP 200 หรือหน้าตาอย่างเดียว
5. empty, loading, error, partial, stale และ permission ถูกตรวจแยกจากกรณีมีข้อมูล

ถ้า inventory ฝั่ง ZORT ยังไม่ครบ ให้เขียนว่า **ยังคำนวณเปอร์เซ็นต์ไม่ได้** การใช้เฉพาะจำนวนรายการที่รู้เป็นตัวหารจะสร้าง 100% ปลอม

## ลำดับใช้จริงหนึ่งรอบ

1. ผู้ที่ล็อกอิน ZORT เก็บ inventory ของจอด้วย role ที่ร้านใช้จริง เปิด dropdown/tab/modal ทุกอันโดยไม่กดยืนยันคำสั่งทำลายข้อมูล
2. ผู้ตรวจกรอกแถว atomic ก่อนเริ่มแก้ เพื่อให้ตัวหารนิ่ง เพิ่มสิ่งที่พบใหม่ได้แต่ห้ามลบแถวเพื่อให้เปอร์เซ็นต์สูงขึ้น
3. จับคู่ข้อมูลตัวอย่างและขอบเขตเดียวกัน แล้วตรวจ read-only ก่อน
4. ปุ่มเขียนใช้ข้อมูลมูลค่าน้อยที่อนุมัติ อ่านผลกลับ และทำ rollback/void ที่พิสูจน์ได้
5. บันทึก error/empty/partial/stale/permission และ mobile แยกจาก happy path
6. รันตัวตรวจเอกสาร แล้ว commit หลักฐานพร้อมเวลาและ source/deploy commit
